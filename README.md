# 作品集工作入口

本資料夾是作品集從專案探索、內容定稿到頁面製作與發布的工作入口。訪談、事實、來源與規範保存在本儲存庫；唯一案例正文、網站程式與頁面素材保存在 [portfolio-website](https://github.com/summywang/portfolio-website)。依用戶授權的工作範圍推進；只要求內容時，完成定稿即可交付。

## 啟動

1. 讀本檔與 [專案總覽](專案總覽.md)，找到目標專案的入口。
2. 做特定專案時，讀該專案的 `專案筆記.md`，確認階段與下一步；已有案例時，寫作或修訂再讀 網站案例資料檔。
3. 依下表載入當前需要的文件。已有答案不重問；一般工作不必讀完整資料夾，系統稽核才全面檢查。

## 工作流程概述

1. **建立專案**：筆記、素材與入口。
2. **訪談與素材盤點**：釐清核心故事、責任、決策與證據，補齊影響主張的缺口。
3. **直接製作中文網站**：直接編輯網站案例資料檔並使用正式模板，含真實圖片、輪播及手機版。
4. **圖文與互動共同修訂**：在同一網站調整文案、排版與操作；中文確認後製作英文。
5. **驗收與交付**：檢查內容與網站、同步兩庫；部署沿用同一份程式。

各步驟的完成條件、狀態與紀錄方式以 [作品集工作流程](作品集工作流程.md) 為準。建站時另讀 [網站實作說明](https://github.com/summywang/portfolio-website/blob/main/docs/content-to-website.md) 的實作細節。分享整套工作方式時，從本 README 開始，並讓接手者取得所需私有儲存庫與素材的存取權。

## 專案工作檔案

所有新專案從 [模板](projects/_template/) 建立在 `projects/<project>/`，資料夾用小寫 kebab-case。

| 檔案 | 唯一職責 |
|---|---|
| `專案筆記.md` | 內部工作：只保留當前狀態、已確認事實、決策、素材、待確認與接續點；歷史由 Git 追溯 |
|網站案例資料檔| 網站 `src/data/cases/<slug>.ts`：唯一中文正文，作者與 AI 直接共同編輯 |
|網站英文案例資料檔 | 中文確認後於網站建立英文版本；保留中文並共用元件 |
| `assets/` | 截圖、流程、影片與原型；命名與登記方式見工作流程 |

每種內容只保留一個正式來源，不建立重複版本。舊 `fact_sheets/`、`discovery_notes/` 僅保留轉址，不再建立或維護第二套模板。規則變更修改所屬文件；入口與其他文件只連結，不複製整段規定。

判斷方式：**討論與查證寫筆記；要給讀者看的內容直接寫網站案例資料檔。** 初稿、修訂、定稿用筆記中的階段區分，不另外複製版本。
