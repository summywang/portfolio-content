# 作品集工作入口

本資料夾是作品集從專案探索、內容定稿到頁面製作與發布的工作入口。內容保存在本儲存庫；網站程式與頁面素材保存在 [portfolio-website](https://github.com/summywang/portfolio-website)。依用戶授權的工作範圍推進；只要求內容時，完成定稿即可交付。

## 啟動

1. 讀本檔與 [專案總覽](專案總覽.md)，找到目標專案的入口。
2. 做特定專案時，讀該專案的 `專案筆記.md`，確認階段與下一步；已有案例時，寫作或修訂再讀 `案例.md`。
3. 依下表載入當前需要的文件。已有答案不重問；一般工作不必讀完整資料夾，系統稽核才全面檢查。

## 工作流程概述

1. **建立專案**：建立專案筆記、素材目錄與總覽入口。
2. **專案探索**：透過素材與問答釐清事實、故事、決策及證據，整理進專案筆記。
3. **案例組織與撰寫**：依八章架構完成同一份 `案例.md` 的配置與正文。
4. **內容修訂與定稿**：核對文字、來源與素材，交付定稿內容。
5. **內容轉網頁準備**：確認案例與模板的對應、素材及缺口，在既有筆記記錄實作安排。
6. **頁面製作與驗收**：建立獨立案例頁、預覽與檢查，提交並推送網站變更。
7. **網站發布**：依授權部署已驗收版本，檢查並交付正式網址。

各步驟的完成條件、狀態與紀錄方式以 [作品集工作流程](作品集工作流程.md) 為準。建站時另讀 [網站交接文件](https://github.com/summywang/portfolio-website/blob/main/docs/content-to-website.md) 的實作細節。分享整套工作方式時，從本 README 開始，並讓接手者取得所需私有儲存庫與素材的存取權。

## 專案工作檔案

所有新專案從 [模板](projects/_template/) 建立在 `projects/<project>/`，資料夾用小寫 kebab-case。

| 檔案 | 唯一職責 |
|---|---|
| `專案筆記.md` | 內部工作：只保留當前狀態、已確認事實、決策、素材、待確認與接續點；歷史由 Git 追溯 |
| `案例.md` | 對外內容：步驟 3 起的八章配置與英文正文，同一檔修到定稿 |
| `assets/` | 截圖、流程、影片與原型；命名與登記方式見工作流程 |

每種內容只保留一個正式來源，不建立重複版本。舊 `fact_sheets/`、`discovery_notes/` 僅保留轉址，不再建立或維護第二套模板。規則變更修改所屬文件；入口與其他文件只連結，不複製整段規定。

判斷方式：**討論與查證寫筆記；要給讀者看的內容寫案例。** 初稿、修訂、定稿用筆記中的階段區分，不另外複製版本。
